## 1. 起因：31 条里有 20 条"机器修了，但一条没少"

`tools/fix_review_findings.py` 能自动改 20 条溯源（`clause_no` → 锚点实际所在条款），
写盘后**队列仍是 31 条**。

### 1.1 分诊：没有一条是"选错了条款"

`_tmp/diag_clause_spread.py` 对 24 条"锚点挂错条款"的事实题做分档：

| 分档 | 条数 | 形态 |
|---|---|---|
| **A 单条款（纯"选错了条款"）** | **0** | — |
| B 邻接多条款 | 18 | `1.3.1/1.3.2/1.3.3`、`3.3.1(1)/3.3.1(2)`、`1、作业事项/2、作业内容` |
| C 远隔多条款 | 2 | |
| D 原文里根本找不到 | 4 | 真问题（出处文档选错 / kp 是改写） |

🔴 **A 档为 0** → 这不是"数据错"，是 **`clause_no` 这个单值字段表达力不够**：
一条题的多个 key_point **天然分散在多个相邻条款**里，
**无论把单值改成哪个，总有 kp"挂错"**。

### 1.2 附带发现：154/159 条事实题的溯源早就脱节

`clause_no` 是 M2 时代的字段，而 key_point 后来被 LLM 重写过**两轮**
（第五轮换整句、第六轮限定出处文档）→ **97% 的事实题**的 `clause_no`
与 kp 实际位置不一致。
而 `clause_no` 恰恰是人工核对时**唯一可看的定位信息**。

---

## 2. 改法：溯源从「单条款」升级为「条款集合」

| 项 | 内容 |
|---|---|
| 新字段 | `clause_nos`（**列表**）= 该题所有锚点实际所在的条款，按文档内位置排序 |
| `clause_no` | 保留（原值若仍在集合里就保留，否则取位置最靠前的那个）—— **向后兼容** |
| `clause_nos_source` | `"relink_2026-11-09"`（留痕，可追溯哪一版工具写的） |
| 核对判据 | `tools/review_eval_set.py` 的溯源 scope 从「单条款」改为「**条款集合的并集**」 |

### 2.1 适用范围：只对**事实题**自动重挂

* 事实题的 kp 是**长句**（30+ 字）→ 定位可靠；
* 数值题的锚点是**短数字串**（"150 mm"）→ 在文档里多处命中，
  "位置最靠前"那个未必是出处条款 → **定位不可靠，不自动改**；
* 版本陷阱题 / 跨文档推理题的溯源是文档级（`expect_doc_id`），不依赖 `clause_no`；
* 拒答题没有原文断言。

### 2.2 🔴 改动隔离（字段级 diff）

```
变更字段统计: {'clause_no': 86, 'clause_nos': 154, 'clause_nos_source': 154}
key_points 未变: 306 / 306      question 未变: 306 / 306
question / question_type / gold_answer / must_include_numbers /
expect_doc_id / time_mode / query_time / key_point_source: 变化 0 条
```

→ **只碰了溯源**，题干 / 答案 / key_point / 锚点 / 题型 / 时间口径**一个字没动**。

### 2.3 ⚠️ 不影响已发布的召回数字

`tools/run_retrieval_eval.py::build_gold` 算 gold 区间用的是
**候选池的 `clause_char_start/end`**（切片时的字符偏移），**不读题集的 `clause_no`**
→ 溯源修正**不污染召回指标**（Recall@5 / content_coverage 保持原值）。
