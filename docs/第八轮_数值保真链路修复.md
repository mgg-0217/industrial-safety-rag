## 1. 抽取侧：4 处缺陷（都是"单例看着都对，组合起来才炸"）

### 1.1 ① 单位分支**顺序** = 优先级（K-81）

```python
r"(...|m³|m3|m²|m2|mm|cm|m|km/h|...|kg|mg/m³|ppm|mg|...)"
#                        ↑ 单字母 m 在前          ↑ 复合单位 mg/m³ 在后
```

正则交替**从左到右优先** → 对 `"10mg/m3"`，在 `m` 分支就命中
（`m` 后面**不要求**任何东西）→ 剩下 `"g/m3"` 被丢弃 → 锚点 = **"10 m"**。

→ 复合单位前移 + 后向断言 `(?![A-Za-z²³])`。

### 1.2 ② 单位白名单比较**没做小写化**

`NUM_RE` 捕获的 `unit` 是**原文的大小写**（`KPa`），而 `ENGINEERING_UNITS` 里写的是
`kPa` → 直接比较会**丢掉原文大写的单位** → `"35～50KPa"` 匹配成功却被白名单过滤掉。

→ 比较前统一 `.lower()`（`_UNITS_LOWER`）。

### 1.3 ③ 前置断言用 `\w` —— **Python 的 `\w` 含中文**

`(?<![\w.])` 在 `"正常操作压力为35～50KPa"` 里失败（"为"是 Unicode 字母 → 是 `\w`）
→ **整段漏抽**，只剩孤零零的 `"50 KPa"`。

→ 改成 `(?<![0-9A-Za-z.])`（只排除 ASCII 数字/字母/小数点）。

### 1.4 ④ 平方单位被丢掉

`"25 mm²"` 被抽成 `"25 mm"`（平方没了）→ 锚点与答案对不上
（答案写 "25 平方毫米"、锚点写 "25 mm" → 判定不命中）。

→ `NUM_RE` 负向断言排除上标 + 新增 `AREA_RE`（`mm2`/`cm2`/`m2` 及其上标变体）。

### 1.5 ⑤ 范围值整段抽不出来（附带发现）

`NUM_RE` 的 `\s*` 不吃 `"～"` → `"35～50KPa"` **整条抽不出来**
→ 那道题的数值保真判据**没有分母**（`must_include_numbers` 为空 → 质检报"空锚点"）。

→ 新增 `RANGE_RE`（`35～50KPa` → `35～50 KPa`，**保留原文分隔符**，
否则溯源时逐字不可达）。

## 2. 评分侧：单位归一化补全 4 处（`src/normalize.py`）

🔴 **锚点修对了但评分对不上，等于没修** —— 所以评分侧必须同步。

| 缺陷 | 现象 | 修法 |
|---|---|---|
| 上标变体不等价 | 锚点 `mg/m3`、答案 `mg/m³` → 不命中 | `_unify_superscript`（`³`→`3`、`²`→`2`）**先做** |
| 复合单位折不掉 | `fold_unit` 的 `(?<=\d)` 对 `"mg/m3"` 不成立（'m' 前面是 'g'） | 复合单位**整串**入表（`mg/m3`→`毫克/立方米`） |
| 中文单位对不上 | 锚点 `0.5 MPa`、答案 `0.5兆帕` → 不命中 | 补 `mpa/kpa/kw/kva/mva/hz/khz/mhz` 等映射 |
| 平方单位不等价 | `25 mm²` vs `25 平方毫米` → 不命中 | 补 `mm2`/`cm2` → `平方毫米`/`平方厘米` |
| 范围分隔符不等价 | `35～50KPa` vs `35-50KPa` → 不命中 | `_unify_range_dash`（`～`/`~` → `-`，**不动负数**） |

## 3. 锚点修正：4 条确定性修复 + 7 个待人工

`tools/fix_numeric_anchors.py` 只做**确定性**修复，三道闸门：

1. **锚点在原文里不可达**（用与评分同源的 `contains_num` 判定）；
2. **候选唯一** —— 用修好的 `extract_numbers` 从出处文档重抽，
   数值部分相同 **且单位兼容**（原单位是候选的前缀）；
3. **量纲族一致** —— 题干问"供气时间"、候选是 `15 MPa` → **不修**
   （治不了根子，还可能**制造虚假高分**：模型答压力就算命中，但它根本没回答时间）。

🔴 **第 2 道闸门的必要性**：只按"数值相同"匹配会把
**`"40 MPa"` 配到 `"40 %"`**（压力配成百分比）→ 加单位前缀约束后拦住了。

* **组 1 → 组 2（-1）**：新归一化把 `"25 mm"`（丢了平方）与答案 `"25 mm²"` 判成不匹配
  → **归一化修正暴露了锚点本身错**，不是变差；
* **组 2 → 组 3（+4）**：锚点修对后，3 道题从 0 命中变成命中
  （`t_30a2197e828d` 0→1、`t_8022668e309a` 0→1、`t_81a2c3613ba4` 0→1）；
