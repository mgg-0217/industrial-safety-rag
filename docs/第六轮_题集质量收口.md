## 1. 质检判据换字段：`gold_answer` → 来源文档正文

### 1.1 起因

第五轮 §2.2 发现「key_point 不可达」从 4 条涨到 46 条，
根因是**质检判据查错了字段**：
`tools/check_test_set.py` 用 `src/eval_align.py::alignment_source` 取源，
而该函数对**事实题返回 `gold_answer`** —— 那是 M2 时代按 `clause_no`
机械切片的产物（切点落在词中间，甚至跨两个条款）。
而 key_point 早就改成从**检索证据**里提炼 → **字段对不上**。

### 1.2 修法：拆成两个源

| 函数 | 用途 | 事实题的源 |
|---|---|---|
| `alignment_source` | **对齐**（`fix_key_points.py` / `relink_test_set.py`） | `gold_answer`（要的是"那个条款"） |
| `qc_source`（新增） | **质检可达性** | **来源文档正文** |

⚠️ 对齐流程**故意不动**：把对齐源换成整篇正文，会把 kp 对到**别的条款的相似句**上
（应急预案之间的通用套话一字不差）→ 反而更糟。

### 1.3 🔴 顺带发现：判据在长文本上会"松掉"

换源之后不可达数从 46 掉到 3 —— **太干净了**，可疑。
`check_key_point_reachable` 的第三级判据是「字符集覆盖率 ≥ 0.8」，
这在**短文本**（切片）上是个真约束，在**整篇文档正文**上**几乎必然成立**
（高频字把覆盖率拉满）。

松紧诊断（`_tmp/diag_kp_judge_strictness.py`，458 个 kp）：

| 判据 | 不可达 kp 数 |
|---|---|
| A　`gold_answer` + 三级判据（第五轮口径） | 67 |
| B　文档正文 + 三级判据 | **3** ← 假阴性 |
| C　文档正文 + 连续 12 字锚定 | 63 |
| D　文档正文 + 最长公共子串 ≥ 0.8 | 69 |

B 判可达、C 判不可达的 **60 条**里，绝大多数是**真·跨文档套话**
（"特种设备事故应急救援工作坚持'以人为本'的理念…"在多份预案里一字不差）
→ **B 把真问题放过去了**。

→ **判据 v2**：长源（`doc_md`）**禁用「字符集覆盖」级**，只走
「归一化后完全包含」→「前缀包含（85%）」两级。
（`tools/check_test_set.py::REACHABILITY_JUDGE = "v2"`）

修正后不可达 **27 条** —— 与第五轮 §2.2 的 C1 箱（27 条）**独立吻合**。

## 2. key_point 根因修法：检索限定在出处文档内

`tools/refine_key_points_llm.py --restrict-to-doc`：
把提炼 key_point 的检索**限制在题目的出处文档内**，且要求每个 kp
**逐字出现在该文档正文里**（机器校验，不通过就跳过该题、保留旧 kp）。

* 159 条事实题，**成功精修 145 条**，跳过 14 条
* 改写 kp 的题：**106 条**

## 3. 🔴 本轮最重要的发现：**两个工具用两套口径 → 结论自相矛盾**

`tools/rescore_provenance.py` 判"kp 是否在出处文档里"用的是
**只去空白**的归一化；而 `src/scoring.py::key_point_hits`（覆盖率判分）
用的是 `src/normalize.py::match_norm`（**标点折叠** + 去空白 + 小写）。

同一批 kp，两套口径：

| 口径 | 判出的跨文档 kp |
|---|---|
| 只去空白 | **41** |
| 去标点（与评分同源） | **10** |

**31 个是标点差异造成的假阳性**：全角/半角括号、中英文引号、破折号。

🔴 **修正后，第五轮的一个结论被推翻**：

| 题型 | 第五轮说"跨文档 kp" | 修正后 |
|---|---|---|
| 版本陷阱题 | **20 / 59（34%）** | **0 / 59** |
| 跨文档推理题 | 10 / 40 | 2 / 40 |
| 事实题 | 48 / 280 | 40 / 280 |

→ 第五轮 §2.3 的结论 2「**版本陷阱题受影响最大**，20/59 的 kp 是跨文档套话，
而它的严格覆盖正是被这批套话撑起来的」—— **整条作废**：
版本陷阱题的 kp **全部**逐字来自它的出处文档（`yulin_2023_old` / `yulin_donghuo_xianshi`），
只是标点写法不同。

🔴 **教训（与 K-66 同源）**：
**「凡是新发现，先问：这条结论有第二个实现吗？」**
—— 这次不是"结论有第二个实现"，而是**同一个量在两个工具里用了两套归一化**。
→ 已把两个工具统一到 `match_norm`（并额外剥零宽字符，语料里确实有）。

## 4. 配对对照：同一批答案，零 API 成本

🔴 key_point **不进提示词**，只用于评分 → 换一套 key_point 重判同一批答案，
**所有变化都来自标尺**，不代表模型行为变化。
批次 `20261106_0933`（主集 306 题），判据 `src/scoring.py::key_point_hits`。

| 事实题指标 | 旧 kp | 新 kp（限定出处文档） | 变化 |
|---|---|---|---|
| kp 总数 | 280 | 267 | −13 |
| **跨文档 kp** | 40（14.3%） | **6（2.2%）** | **−85%** |
| 软覆盖 | 0.6321 | 0.6442 | +0.012 |
| **严格覆盖** | 0.0500 | **0.0375** | **−0.013** ↓ |
| 题目级全命中 | 0.5283 | 0.5535 | +0.025 |
| **出处文档被引率** | 0.9119 | **0.9119** | 不变 |

🔴 三条解读：

1. **严格覆盖下降不是模型变差**：新 kp 更长、更贴原文（不是碎片），
   "逐字命中"的难度天然更高 —— 与第五轮 §2.1 同一个机理（碎片容易凑）。
2. **出处文档被引率一字未变**（0.9119）→ 印证 **key_point 不进提示词**，
   模型行为完全没被影响。
3. **软覆盖与全命中略升**，但**不能**说"质量提升"——
   第五轮 §1.4 已经证明这类提升可能只是**字数效应**（`tools/diag_length_confound.py`）。
