🔴 **多路索引方案被实测证伪了。** 三种变体（RRF 融合 / 合并索引 / 整表块并入）

真正解决问题的是另外两件事：

1. 🔴 **主索引换成 `structural`**（块边界 = 标题边界，表天然完整）
   → **等字符预算**（2500 字符）下：总体覆盖度 **0.871 → 0.916**、

2. 🔴 **加大 top-k 会让题型分化，没有全局最优**：

**"该召回的表没召回"这件事，一半不是表的问题，是上下文装不下；

（六个策略的块长从 107 到 501，固定 top-k 下它们的上下文预算根本不同）。
固定 top-5 时 fixed 的覆盖度看着更高，**等预算下完全反过来**。

## 1. 先补一个指标：内容覆盖度

M5 的 `Recall@k` 是**二值命中**：top-k 里有一块与 gold 区间重叠就算命中。
但对表格题来说，**命中一块碎片 ≠ 能答对** —— 模型要的是那张表的限值，
碎片里可能只有半张表。

→ 本次诊断新增一个**连续指标**（不是 PRD 原有指标，是本次加的）：

```
coverage = |top-k 命中块的字符区间并集 ∩ gold 区间| / |gold 区间|
```

gold 区间取自候选池的条款原始 md 偏移，**与索引怎么切无关** →
**跨策略可比**，这是它比 R@k 好用的地方。

| | R@5 | 内容覆盖度 |
|---|---|---|
| 含义 | top-5 里有没有一块碰到答案 | 上下文里**带进了多少**答案内容 |
| 粒度 | 二值 | 连续（0–1） |
| 跨策略可比 | ❌（gold 按各策略的 chunk 偏移定义） | ✅（gold 区间来自原始 md） |

## 2. 五个方案的实测结果

题集：198 道条款级可评题（事实题 + 数值题）；表格类题 12 道。

| # | 方案 | R@5 | 总体覆盖度 | **表格题覆盖度** | 变差的题 |
|---|---|---|---|---|---|
| — | **基线：fixed 单路 top-5** | **0.854** | **0.871** | 0.390 | — |
| ① | fixed + table **RRF 融合**（等权） | 0.793 | 0.805 | 0.435 | **12 道** |
| ② | fixed + table **RRF 融合**（权重 0.2–0.7） | 0.854 | 0.871 | 0.390 | 0（辅助路**一个都进不去**） |
| ③ | fixed + table **合并索引**（单路） | 0.798 | 0.845 | 0.347 | — |
| ④ | structural 单路 top-5 | 0.854 | 0.848 | **0.517** | — |
| ⑤ | structural + table_whole **合并索引** | 0.854 | 0.848 | 0.517 | 0（整表块**一个都进不去**） |

### 2.1 为什么等权 RRF 会掉 6 个点

**辅助路平均占掉 top-5 的 2 个名额（40%）**，把主索引的正文块挤了出去。
12 道题从"命中"变成"不命中"。

根因是 **RRF 只用排名、不用分数**（PRD 4.3 的设计）→ 权重是**门槛式**的：

| 辅助路权重 | 辅助路进入 top-5 的块数 | 结果 |
|---|---|---|
| 0.2 / 0.3 / 0.5 / 0.7 | **0 / 5** | 辅助路第 1 名 `0.7/61 = 0.0115` < 主路第 5 名 `1/65 = 0.0154` → **永远挤不进去** |
| 1.0 | 2 / 5 | 进来了，但**挤掉正文** |

→ **RRF 融合对"补充一路新内容"这件事天然不友好**：
新路要么全进（挤占名额），要么全不进（门槛效应），**没有中间态**。

### 2.2 为什么合并索引也掉

主索引里本来就有表格的**碎片**（fixed 切分把表切碎混进正文）。
再把整块表格并进去 → **同一张表在索引里出现两次** → 两份都拿高分 →
**top-5 被同一张表占满** → 正文块被挤掉。
表格题 R@5 从 0.750 掉到 **0.333**。

### 2.3 为什么整表块（策略 4b）进不去

策略 4b 产出的整表块均长 **816 字符**（vs 按行切 294），BM25 的长度归一化
（`b=0.75`）直接把它们压到后面 → **116 块一个都进不了 top-5**。
→ 长块不是免费的：它换来了完整性，代价是**在等长竞争里出局**。

## 3. top-k 敏感性 + **等字符预算**（单路，无辅助路）

### 3.1 🔴 固定 top-k 对不同块长的策略**不公平**

各策略的块长差 3 倍（fixed 均长 501 / structural 169 / clause 107），
**固定 top-5 时，装进上下文的字符数差 3 倍**：

| 主索引 | 块均长 | top-5 装进的字符 |
|---|---|---|
| fixed | 501 | 2505 |
| structural | 169 | 845 |
| clause | 107 | 535 |

→ 要谈"哪个策略更好"，必须**按字符预算对齐**，
而不是按块数对齐。诊断工具因此加了 `--char-budget`
（`top_k = 预算 / 该索引的平均块长`）。

### 3.2 等预算（2500 字符）下的完整结果

| 主索引 | 块均长 | 实际 top-k | R@5 | **总体覆盖度** | **表格题覆盖度** | 加多路后总体覆盖度 |
|---|---|---|---|---|---|---|
| fixed | 501 | 5 | 0.854 | 0.871 | 0.390 | 0.837 ❌ |
| **structural** | 169 | **15** | **0.854** | **0.916** | **0.685** | 0.837 ❌ |
| clause | 107 | 23 | 0.823 | 0.915 | **0.695** | 0.768 ❌ |

**🔴 这一行推翻了固定 top-k 下的结论**：
固定 top-5 时 fixed 的总体覆盖度（0.871）看着比 structural（0.848）高，
**等预算下完全反过来**（0.871 vs **0.916**），
表格题更是 **0.390 vs 0.685**（差 29.5 个点）。

> 🔴 **教训**：**跨切分策略比较时，必须按字符预算对齐，不能按块数对齐**。
> 上一轮"六策略召回差距不显著"的结论就带着这个隐患 ——
> 六个策略的块长从 107 到 501，固定 top-k 下它们的上下文预算根本不同。
> 本报告只把 **R@5** 当作可横比的指标（R@5 的契约就是"前 5 名"，与块长无关），
> 覆盖度一律在等预算下比较。

### 3.3 top-k 敏感性（固定块数口径，用于看趋势）

| 主索引 | 指标 | top-5 | top-8 | top-12 |
|---|---|---|---|---|
| fixed | 总体覆盖度 | 0.871 | 0.907 | 0.916 |
| fixed | 表格题覆盖度 | 0.390 | 0.435 | 0.493 |
| structural | 总体覆盖度 | 0.848 | 0.885 | 0.900 |
| structural | 表格题覆盖度 | 0.517 | 0.676 | 0.684 |
| 两者 | R@5（恒定） | 0.854 | 0.854 | 0.854 |

**两条读数**：

1. 🔴 **R@5 恒定、覆盖度却在涨** —— 说明"没召回到"和"召回到了但没带全"
   是**两件不同的事**，而 M5 的 R@5 只看得见前一件。
   上一轮"六策略召回差距不显著"的结论**掩盖了覆盖度上的真实差距**。
2. 🔴 **structural 在表格题上每个 top-k 都大幅领先**（0.517/0.676/0.684
   vs 0.390/0.435/0.493）→ 表在 structural 里是**完整的**（块边界 = 标题边界），
   在 fixed 里是**碎的**。

### 4.3 四条读数

**① 🔴 换主索引的收益集中在"引用定位"，答案质量基本持平**

条款可定位率 0.000 → 0.958（top-5）/ 0.970（top-8），
而**严格口径下事实题 0.168 = 0.168**（top-5 两组完全相同）、
数值精确匹配 0.506 = 0.506。
→ 换索引**不花钱**（质量不掉）就换来引用能落到条款上。

**② 🔴 换主索引没有破坏版本治理**

版本陷阱题的版本命中率三组都是 **1.000**，事实题 0.975 / 0.975 / 0.987，
上下文里的过期 chunk 三组都是 **0**。
→ 这是 PRD 4.4 那条**推论**（"版本治理与用向量还是 BM25 无关"）的**同构实证**：
**它也与用哪种切分策略无关**。

**③ 🔴 加大 top-k 会让题型分化 —— 没有全局最优的 top-k**

| 题型 | top-5 → top-8 的变化 | 解释 |
|---|---|---|
| **数值题** | 覆盖 0.570 → **0.620**，精确匹配 0.506 → **0.557** | 多几块 → **限值表更可能是完整的** |
| **事实题** | 覆盖 0.410 → **0.375**，严格 0.168 → 0.141，全命中 0.258 → 0.201 | 🔴 **噪声变多，注意力被稀释** |
| 版本陷阱题 | 覆盖 0.633 → 0.667，严格 0.133 → 0.100 | 混合 |
| 拒答误答率 | 0.095 → 0.071 | 略好 |

→ 🔴 **检索层的覆盖度随 top-k 上升，端到端的答案质量却题型分化** ——
**"带进更多内容"不等于"答得更好"**。
数值题要的是"那张表"（多几块才凑得齐），事实题要的是"那一条"（多几块只是噪声）。

**④ ⚠️ 拒答：structural 三组都略差于 fixed**

误答率 fixed+top-5 **0.024**（1/42）vs structural+top-5 **0.095**（4/42）
vs structural+top-8 **0.071**（3/42）。
方向说得通：`structural` 的块更贴合条款、上下文信息更全 →
模型更容易"找到点什么"来回答，而不容易老实拒答。
**但 CI 大幅重叠、n=42 太小，不能断言显著** —— 待验证项，不是结论。

### 4.5 推荐配置

**`structural` + top-k 5**：

| 理由 | 证据 |
|---|---|
| 引用能落到条款 | 条款可定位率 **0.958**（fixed 是 0.000） |
| 答案质量不亏 | 事实题严格口径 **0.168 = 0.168**，数值题严格 0.494 > 0.443，跨文档题严格 0.164 > 0.127 |
| 版本治理完全不受影响 | 版本陷阱题版本命中 **1.000**，上下文过期 chunk **0** |
| 拒答更稳 | 误答率 0.095 vs fixed+top-8 的 **0.143** |

⚠️ **但 top-k 没有全局最优**：`top-8` 的数值题明显更好（精确匹配 0.557 vs 0.506），
事实题更差、拒答更差 → **按题型选**：
- 默认（事实题占 52%）→ **top-5**
- 数值/限值类问题 → **top-8**（+5.1 点精确匹配）

⚠️ **top-15（等 2500 字符预算的等效点）待补** ——
检索层在等预算下覆盖度最高（0.916），但端到端是否更好要实测。

### 4.6 这节还欠什么

- 🔴 **"加大 top-k"这一项在端到端还没有可信数据**：
  检索层已经测出覆盖度随 top-k 上升（0.871 → 0.907 @top-8），
  但**检索层的覆盖度不等于生成层的答案质量** ——
  上下文变长也会带来噪声。这是必须补跑的。
- `fixed + top-8` 与 `structural + top-8` 两组的**完整 306 题**数据。

**补跑清单**（额度恢复后按顺序跑，两组之间不要并发 ——
并发 6 会撞速率限制，并发 3 才稳）：

```bash
python tools/probe_llm.py                                        # ① 先探端点
python tools/run_generation_eval.py --configs retrieval --strategy structural --top-k 8 --tag k8
python tools/run_generation_eval.py --configs retrieval --strategy fixed      --top-k 8 --tag k8
python tools/compare_qid_subset.py \
    --a "fixed+top5=eval_runs/20261104_0950_generation_retrieval_main.answers.jsonl" \
    --b "structural+top8=eval_runs/<ts>_generation_retrieval_k8.answers.jsonl"
```

⚠️ **跑之前先 `probe_llm.py`**：额度不足时，`run_generation_eval.py` 会
**先把能答的答完再开始失败**（前半段正常、后半段全 429），
让人误以为是"某些题型特别难"——实际上只是额度耗尽的时间点。
本轮就踩了：跑了 2.5 小时、81 题成功、225 题失败。
**额度探测应该放在批次开始之前，而不是事后。**

## 5. 这一轮挖出的坑

全部记在 `notes/踩坑.md`（K-45 ~ K-48）：

| 编号 | 一句话 |
|---|---|
| **K-45** | 🔴 多路 RRF 的**坐标系撞车** —— 各路 idx 不是同一坐标系，第二路被整路吞掉，症状像"方案没用" |
| **K-46** | 🔴 RRF 的权重是**门槛式**的 —— 辅助路要么全进（挤掉 40% 名额）要么全不进，**没有中间态** |
| **K-47** | 🔴🔴 命中判定**没截断到 top-k** → 一个失败的方案被算成"提升 4.5 个点"，**结论完全反转** |
| **K-48** | 指标标签会随参数**漂移** —— "R@5"其实是 R@top-k，扫参数时三组数字不可比 |

🔴 **K-47 最值钱**：它让我差点得出"多路索引有效"的结论。
**指标变好看时先怀疑指标** —— 涨得越漂亮，越要查口径。

## 6. 结论与后续

1. 🔴 **README「下一步」第 4 项的方案（多路索引）不成立** —— 实测三种变体全负。
   保留这段实测不是为了否定它，而是为了让"为什么没做多路索引"有据可查。
2. **替代方案：主索引用 `structural`**。这与上一轮的结论一致
   （条款可定位率 fixed 0.000 → structural 0.958），两条独立证据指向同一个选择：
   检索层（等预算下覆盖度 +4.5 点）与生成层（引用定位 +95.8 点、答案质量持平）。
3. 🔴 **top-k 不是"越大越好"，也不是检索技巧，是上下文预算旋钮** ——
   它在检索层提高覆盖度，在生成层却让题型分化
   （数值题受益、事实题受损）。**没有全局最优值**。
   要定它，得先说清楚"服务哪类问题"。
4. 🔴 **跨切分策略比较必须按字符预算对齐**（本报告新增的方法论约束）。
   六策略块长 107–501，固定 top-k 下的横比是**在比不同的上下文预算**。
   → 已加进 PRD 3.3 的判定规则。
5. ✅ **"内容覆盖度"已加进 M5 的常规指标**（`tools/run_retrieval_eval.py` 现在每个批次都带
   `content_coverage` 字段）。它比 R@k 多回答了一个问题：
   *召回到了，但带进上下文的内容够不够回答*。
6. **待验证**：拒答误答率在 structural 上略差（1/42 → 4/42）——
   n=42 测不出显著，要坐实需把拒答题扩到 150+ 条。
