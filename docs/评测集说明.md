## 二、为什么必须造这三类题

候选池 842 条里只有事实题和数值题，且 **576/842（68%）** 的题干是
`clause_no` 被当正文切片后的产物（切点落在词中间）——补字修不好，必须 LLM 重写。

- **版本陷阱题**：语料里唯一的真实版本链是「榆林〔2023〕26号 → 榆林〔2025〕1号」
  （新版明示废止旧版）。成对出题：**同一主题，一个问 2023 年末（应命中旧版），
  一个问现行（应命中新版）**。时点口径按 PRD 定死的**年末口径** `as_of(Y-12-31)`，
  不用 `Y-01-01`（2023 版生效日 2023-12-07，取 01-01 会落进"空档"）。
- **拒答题**：用**实测验证过的 40 个安全假位号**（原文 + 归一化双口径精确验证）
  构造"语料里没有这台设备"的问题。真实位号实测**恰好 5 个**
  （19-V-4215 / 1910-PV-42151 / T-4200 / T-4300 / MP-41009-200-S1B-H1），
  其余 14 个 `equipment_tags` 是设备类别名，不能拿来当"存在"的判据。
- **跨文档推理题**：同一危险源标签出现在 ≥ 2 份文档时，构造需要对比两者的题。

## 三、key_point 的可复核性（判据按题型分源）

PRD 7.3 的 `key_point_coverage` = 命中数 / 总数。
**分母里的每个 key_point 都必须能在原文里字面找到**，否则这个指标是假的。

对齐源按题型分开（实现见 `src/eval_align.py`，质检与规范化共用同一套）：

| 题型 | 对齐源 | 说明 |
|---|---|---|
| 数值题 | `must_include_numbers` | 保真锚点；可达性判定查 `gold_answer` |
| 事实题 | `gold_answer` | 原文切片 |
| 版本陷阱题 | `expect_doc_id` 指向文档的 md 正文 | 🔴 它的 `gold_answer` 原本是 `None` |
| 跨文档推理题 | `expect_doc_id` + `related_doc_ids` 的 md 正文 | 🔴 它的 `gold_answer` 原本是 LLM 的概括 |
| 拒答题 | **无** | key_point 是判分标准（「是否声明查不到」），不是原文断言 |

🔴 **判据用错字段会让 61 条题被误判成"幻觉"**（详见 `notes/踩坑.md` K-13）。
拒答题那一类尤其容易漏：它的正确答案就是「语料里没有」，**压根不指向任何原文**。

对齐规则：把 key_point 用最长公共子串**对齐回原文的具体片段**，用该片段替换 key_point。
门槛只要求公共片段 ≥ 4 字 —— 因为 LLM 写的是**概括性改写**，
按比例门槛（如 60%）实测会误剔 93 个语义正确的 key_point。
只有公共片段为空（真幻觉，如 "50 %"）才剔除，并记入 `orphan_key_points`。

🔴 **对齐后必须去重**（`notes/踩坑.md` K-16）：
对齐可能让两条 kp 撞到同一句话的不同截断（如
「…应配备能够采集全过程作业影像的防爆型摄录设备」和「…应配备能够采集全过程作业影」），
互为子串的只留信息量大的那个 —— 否则 `key_point_coverage` 的**分母被灌水**，
命中一个等于命中两个。实测去掉 **206 个**重复 kp。
去重后分布：2 个 kp 136 条 / 1 个 95 条 / 3 个 52 条 / 4 个 22 条。

⚠️ **key_point 存的是归一化形态**（全角逗号变半角）。
这与判定用的归一化一致（`flat(kp) in flat(source)`），是自洽的；
但人工核对时看到的 kp 与原文标点不完全一致，**别误判成"原文里没有这句话"**。

## 四、质检结果

质检标准见 PRD 7.2，脚本 `tools/check_test_set.py`，报告 `data/eval/check_report.md`。

| 质检项 | 命中 | 说明 |
|---|---|---|
| 🔴 key_point 不可达 | 4 | 全是数值题的幻觉锚点（见下） |
| 题干过短 | 2 | 短于 20 字符 |
| 数值题空锚点 | 1 | 无法做数值保真判定 |
| 事实题缺 key_points | 1 | key_point 被清空，已标 `needs_manual_review` |

**无标记：282 / 306 条（92.2%）**

对照：判据修正前是 221/306（72.2%），其中 60 条"不可达"全是判据用错字段造成的误判。

报告第四节按 **PRD 7.2 的 11 条质检标准逐条**记录了通过情况
（PRD 9 节 M2 的验收标准要求「11 条质检标准逐条记录通过情况」）。
其中第 6 条「陷阱题有唯一正答」是**机器判定**的 ——
用 M1 的 `versioning.is_effective()`（三态）检查期望版本在该时点生效、
且同链其它版本不生效，41 条版本陷阱题**全部通过**。
这条同时是 M1 版本模型与 M2 题目时点口径的**交叉验证**。

### 剩余问题的人工核对要点

- **4 条数值题锚点幻觉**：锚点（如 `50%` / `80%` / `150 mm` / `1000 kg`）在原文里找不到。
  典型是 `t_07947ebc3693`（有限空间气体检测限值）—— 原文那节是**隐患排查表**，
  限值根本不在这一段里，是 LLM 顺着相邻条款编的。
  **处理**：逐条回原文找真实限值改锚点，或直接删题。
- **"量纲对不上"**：题干问的压力/温度，锚点里只有重量/时间。
  同样是锚点抽取错位，改锚点或改题干。
- **题干泄漏答案原句**：事实题里 LLM 改写时把答案片段抄进了题干，会让检索退化成字符串匹配。

## 五、策略 6 的切分（QA-pair 索引侧 / 评测侧）

脚本：`python tools/refine_eval_set.py --stage qa_split`
产物：`data/eval/qa_index_side.csv` / `data/eval/qa_eval_side.csv`

**切分顺序不可反**：不是"把 842 条对半切"，而是"**先定评测集用到哪些条款，
再把这些条款的题排除出索引**"。QA 索引的泄漏单位是**条款**
（同一条款的题问的是同一件事），而实测 842 条分 835 个条款、其中 828 个条款只有 1 条题，
按题对半切必然有一半条款两侧都有。

**不相交校验（当前结果）**：

| 校验 | 结果 |
|---|---|
| 同 `(doc_id, clause_no)` 交集 | **0 组** ✅ |
| 同 `question` 交集 | **0 条** ✅ |
| 索引侧规模 | 640 条（候选池的 76.0%） |
| 评测侧规模 | 201 条 |
| 采用的题干 | **842 / 842 条全部用改写后的版本** |

🔴 **只验条款交集是不够的**（`notes/踩坑.md` K-14）：
不同条款会产出**字面完全相同**的题干（相邻条款共享同一语义短语，
如「办理审批手续」），初版切分因此有 5 组跨侧同题干泄漏。
切分后又加了一道题干级去重。

⚠️ **切分必须用改写后的题干**：策略 6 真正拿去检索的是 chunk = question + answer，
拿模板题干去切分等于在给一个不会发生的检索场景做准备。
（改写后跨侧重复反而降到 0 —— 改写把"不同条款撞出同一句话"的问题一起解决了。）

## 六、策略 6 的题干改写（检索路的前提）

PRD 3.1 策略 6 把 QA 对的 `question + answer` **直接建成 chunk 参与检索**，
所以**题干质量就是这条检索路的上限**。

而 `qa_pairs.csv` 的 842 条题干里 **774 条是机器模板**
（「《文档名》中，{条款语义短语}是怎么规定的？」），三重问题：
不像用户问的；模板词在 842 条里高度重复导致 **BM25 的 IDF 趋近 0**；
tail 是截出来的短语，可能与答案语义弱相关。

改写分两步（脚本 `tools/rewrite_qa_questions.py`）：

1. **回填**：把 `test_set.jsonl` 里已经改写好的 198 条题干直接搬过来（不调 LLM）；
2. **LLM 改写**：剩下的 644 条逐批改写成自然问句，约束是"只依据原文、指向具体规定、
   **文档名原样照抄**、不照抄答案整句、数值锚点不得改动"。

**结果**：842 / 842 条全部改写完成（198 回填 + 644 LLM），平均题干长度 46 字，
唯一题干 838 个（4 组重复，均为**榆林两版的同一条款** —— 版本链的体现，属预期），
**0 条照抄答案原文**。只剩 2 条保留了模板形态（题干含条款号，语义可读，不影响检索）。

产物 `data/eval/qa_pairs_rewritten.csv` 保留原 `question` 列（审计用），
改写结果在 `question_rewritten` 列，来源标在 `rewrite_source` 列
（`backfill` / `llm` / `none`）。

> 🔴 LLM 复制长中文文档名时会吞字或加字（实测
> 「福建泉州中化学天辰(泉州)…」被写成「福建泉州中化学中化学天辰…」），
> 脚本里有 `fix_doc_name()` 统一换回原文（相似度 ≥ 0.75 才替换，避免误伤）。
