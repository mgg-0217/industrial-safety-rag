### 1.4 副作用检查：事实题 —— 🔴 提升**主要来自字数**，不是内容变准

→ 🔴 **提升只出现在"B 明显更长"的那一层**；

→ **结论：这是"字数效应"，不是"内容更准"。**

内容基本相同，只是抄得更全、拆得更细。

→ ⚠️ **不能说"SYSTEM_V3 让事实题质量提升 6.4 点"**。
只能说：**它让答案更长更结构化，覆盖率随之上升，但正确性提升未证实**。
（这正是 K-55「判定分类的计数不能单独作为证据」的延伸 ——
本轮用的是**与判分无关的可观测行为**：答案长度。）

**可以确认的结论**：`system_v3` 在事实题上**没有引入错误** ——

## 2. 🔴 两个已发布数字被重新算过

### 2.1 「事实题严格口径 0.168」→ **0.064**（配对，同一批答案）

上一轮判定「事实题 key_point 是 `clause_no` 机械切片的产物 → 分母里混着垃圾」。
本轮 LLM 重提炼后，**用同一批答案换一套 key_point 重判**（key_point 不进提示词，
所以这是零 API 成本的严格配对）：

| key_point 版本 | 软覆盖 | 严格覆盖 | 题目级全命中 |
|---|---|---|---|
| 旧（碎片，如「试生产前企业开」） | 0.430 | **0.168** | 0.233 |
| 新（整句，如「试生产前企业开展了设备及管道试压、吹扫…」） | **0.679** | **0.064** | **0.585** |

🔴 **两个口径反向**，根因是**分母变了**：

* 碎片**短** → 答案里凑到那几个字就算"逐字命中" → **旧 kp 的严格命中不是因为模型答得准**；
* 整句**长** → bigram 覆盖率高 → **软口径反而变好**。

→ **旧 kp 的 0.168 是往高了灌的**。修完之后数字**更低**（0.064）。
→ 这不是"口径放宽"，是**换了一个更严的标尺**（K-68）。

`tools/diag_kp_reachability.py` 把 67 个不可达 kp 分箱：

| 分箱 | 数量 | 含义 |

## 3. 语料层的"脏"：实测**不影响**检索与生成 → 刻意不清洗

起因：`guide_shijiu_shoujiu` 是从 gzip 里救回来的（没走容器抽取），
manifest 里 `extract_quality=ok` → 按 PRD 2.8 不降权 → 怀疑污染检索。

`tools/diag_boilerplate_impact.py` 实测：

| 层级 | 导航噪声占比 |
|---|---|
| 文档层（7 份 HTML 源） | **11% – 24%**（导航菜单 + 省份列表 + ICP 备案号） |
| 检索层（306 题 × top-5 = 1530 块） | **均值 1.99%**，**≥50% 的块 0 个** |
| 生成层（4823 条已生成答案） | **0 条**含导航文本 |

为什么检索层影响这么小：① 结构性切分把导航行聚成独立短块，BM25 长度归一化压掉；
② 导航词高度重复 → **IDF 极低**。

🔴 **结论：不清洗**。清洗要让所有已发布数字失效（必须全量重跑），
而收益是 0 条答案受影响 —— **代价远大于收益**（K-67）。

⚠️ 顺带修掉一个**诊断脚本自身**的坑：噪声表用文件名（`x.md`）做键，
chunk 用 `doc_id`（`x`）→ 查表永远落空 → 噪声占比恒为 **0.00%**（假阴性）。
已加**覆盖率自检**（断言两侧键集合有交集，否则 `SystemExit`）（K-66）。

## 4. 🔴 更正：所谓"新失败模式"是**我自己的假阳性**

SYSTEM_V3 剩下的 3 条误答里，`r_e935db5ce95c` 的形态看着像新的：

> 「资料中**有**合成氨装置**检维修作业许可**的明确规定」

初版诊断（`tools/diag_corpus_claim.py`，**自带一套正则**）测出
「8/150 条含这类断言，且全部同时有"未找到"表态 → **自相矛盾**」，
本报告初稿据此把它写成"前两轮没见过的新失败模式"。

🔴 **那个结论是错的**，两处都错：

1. **8/150 是假阳性**：宽松的模式把**边界声明句**
   （「以下为通用要求，其适用性不等同于对 X 的专门规定」）
   也判成了假称 —— 而那恰恰是**我们想要的正确行为**。
   还踩了 K-58 同款的**子串陷阱**：「**现有**资料仅能说明…」里的"有"。
2. **"自相矛盾"不成立**：那一句说的是**检维修作业许可**，
   而答案后面说"资料中没有…**动火和受限空间管理**的专门规定" ——
   **两个不同的子项，不构成矛盾**。

🔴 **修正后的实测**（判据改为复用 `src/scoring.py::find_corpus_claim_sentences`，
与代码级兜底同源，消除"两套正则各说各话"）：

| | 数量 |
|---|---|
| 判为"假称语料里有规定" | **1 / 150** |
| 其中**同时也是污染句** | **1** → **不是独立的失败模式** |
| 判为污染句但不是假称 | 2 |

→ 🔴 **结论：它就是原有的"归因污染"**，
不是一类新失败模式，也不需要单独的提示词规则。

**但代码级兜底的那条扩展仍然保留** —— 它是**安全网**：
假称句不一定同时满足污染句的全部条件（本次那条恰好都满足）。
在**本批次上新增划除 0 条**，所以它不改变任何已发布数字。

> 🔴 **这本身就是本轮最值得记的一条**：
> 一个"看起来像重大发现"的结论，被自己的第二个工具推翻了。
> 差别只在于**判据是不是只有一份** ——
> 判据一旦有两份实现，就一定会有一份是假的。

## 5. L1 句向量对照：🔴 换成**真语义模型**，"混合检索提升召回"依然不成立

这是 PRD 4.6 留到今天的那一级。上一轮只能测 L2（TF-IDF+SVD，**不是预训练语义模型**），
所以"向量路是负贡献"这个结论当时**只能算"有迹象"**。

现在装了 `sentence-transformers`（3.4.1）+ `transformers` 4.48.3，
用 `BAAI/bge-small-zh-v1.5`（512 维，中文预训练句向量）跑**同会话、同代码、同数据**的三方对照：

| 切分策略 | 后端 | **V（仅向量）** | **B3（混合）** | **B2′（纯 BM25+过滤）** | 向量路延迟 |
|---|---|---|---|---|---|
| fixed | **L1** bge-small-zh | 0.716 | 0.841 | **0.883** | 3.17s |
| fixed | L2 TF-IDF+SVD | 0.724 | 0.803 | **0.883** | 6.87s |
| fixed | L4 无向量 | — | 0.883 | **0.883** | 0.06s |
| structural | **L1** bge-small-zh | **0.807** | 0.860 | **0.883** | 3.67s |
| structural | L2 TF-IDF+SVD | 0.701 | 0.784 | **0.883** | 7.43s |
| structural | L4 无向量 | — | 0.883 | **0.883** | 0.14s |

（n=264 可评题，`fixed`/`structural` 两个切分策略，版本过滤开，`α=0.5`；
批次 `20261106_1045`(L1) / `20261106_1047`(L2) / `20261106_1049`(L4)，
对照表由 `tools/compare_embed_backends.py` 产出）

### 🔴 三条结论

**1. 混合检索是负贡献 —— 四个格子全部成立**
`B3 − B2′`：L1/fixed **−0.042**、L1/structural **−0.023**、L2/fixed **−0.080**、
L2/structural **−0.099**。
→ 🔴 **换成真正的预训练中文句向量也没能救回来**。
→ 所以 **"混合检索提升召回"这个说法不能写进简历** ——
这条禁令现在的证据比上一轮强得多（上一轮只能拿 TF-IDF 近似去说）。

**2. 语义向量的价值取决于切分粒度**
structural 上 L1 比 L2 高 **10.6 点**（0.807 vs 0.701，CI 不重叠）；
fixed 上反而**略低**（0.716 vs 0.724，CI 重叠）。
→ 块越碎，BM25 的短块匹配越脆，语义向量越有用。
→ 🔴 **"要不要向量路"不是后端问题，是切分策略的函数**。

**3. 向量路慢 8–12 倍，召回还更低**
L1 向量路 3.17–3.67s vs 纯 BM25 0.38–0.56s；
而 R@5 是 0.716/0.807 vs 0.883。

### ✅ 自查通过

`B2′`（纯 BM25 + 版本过滤）在**三个后端下完全一致**（0.883 / 0.883 / 0.883）
→ 差异确实来自**后端**，不是题集或切分变化。

### 最终配置

**L4（纯 BM25）+ 版本过滤 + `structural` 切分** —— 与 PRD 4.6 的预判一致，
而且现在是用**真语义模型**验证过的（不再是 TF-IDF 近似）。

### 🔴 装包/跑批踩的坑（K-71、K-72）

* **pip resolver 回退**：不钉版本时 pip 一路回退到要 `pytorch-transformers` 的远古版本，
  然后卡在 `regex` 上（"from versions: none"）→ 实测 **13–27 kB/s** 的链路下
  这个回退要跑 **50 分钟**还失败。
  → 修法：`pip install --no-deps` + **钉死版本**
  （`sentence-transformers==3.4.1` / `transformers==4.48.3` /
  `huggingface-hub==0.28.1` / `tokenizers==0.21.0` / `safetensors==0.5.2`）。
* **`HF_ENDPOINT` 设得太晚**：`huggingface_hub.constants.ENDPOINT` 在**导入时**就固化了
  → 原写法（先 import 再 `setdefault`）会让它去连本机不可达的 `huggingface.co`。
* **Xet 协议不可达**：`model.safetensors` 会被重定向到 `cas-bridge.xethub.hf.co`
  → 必须 `HF_HUB_DISABLE_XET=1`。
  （以上两条已固化进 `src/embed.py::try_l1`。）
